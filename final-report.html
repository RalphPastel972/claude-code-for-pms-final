Rook Dispatch · Final report · Claude Code for PMs

Release 4.2 took 30 seconds away, and four responders quietly vanished.

4.2 cut the time a responder has to answer a ping from 90 to 60 seconds. The routing code treats a missed ping the same as a "no", and never forgives either. Four responders sank to the bottom of the queue and their phones stopped ringing. Nobody noticed, because their handlers don't file tickets.

Module 5 Keeping it from happening again

4.2 was built exactly as briefed. The briefs were the problem.

Both 4.2 routing briefs were one line, with no owner, no target and no evidence. So I built review-checklist, a skill that reads any brief before it ships and checks four things:

1

Names who owns it

The 60s change had no owner and no written reason.

2

Says how we'll know it worked

A target would have made the day-one jump in misses hard to put down to August.

3

Keeps the same scope start to finish

Proximity was the ask. The timeout came along for the ride.

4

Explains the problem before the fix

No ticket before 4.2 complained about the 90-second wait.

The prompt I wroteMake a skill called review-checklist. When I point it at a brief, it checks that the brief: names who owns it, says how we'll know it worked, keeps the same scope start to finish, and explains the problem before the fix.
